# They are instructions 226-229 of 714. main does the stayClockAt pair FIRST: the load of
# g_serviceClock (fn+0x412) and its store to note+0x30, then the phase store (+0x18) and the
# stayAt store (+0x28). The branch keeps source order: phase (+0x18), stayAt (+0x28), then

# class splitcheck always FAILs.
# CAUSE: g_serviceClock went from internal linkage (anonymous namespace in Scheduler.cpp,
# never address-taken, so MSVC may read it ahead of stores made through a pointer) to
# external linkage (an `inline` variable in scheduler/Scheduler_internal.h, shared by
# Scheduler.cpp and scheduler/CombatScan.cpp), where MSVC must assume the stores could alias it.
# NO ALIASING: the three stores go to three separate fields of one RetreatNote inside a
# g_retreatNotes unordered_map node (heap). The node cannot overlap the global, so both
# orders store the same three values.
# THREADING: ServiceRetreat and every other reader / writer of g_serviceClock run on the
# AddTask worker only (#4). No other thread can observe the order.
# ONE OBJECT: g_serviceClock has one address in the branch builds (O2 0003:126960, /Od
# 0003:125392), referenced from both TUs (Tick, ServiceRetreat, ClearTransientState,
# ServiceClock).
