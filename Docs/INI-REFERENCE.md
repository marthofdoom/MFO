# MFO.ini reference

Every key in `Data/SKSE/Plugins/MFO.ini`, with its default. Generated from the comments in that file, which is the source of truth and ships in the zip. This is the **seed** file. MCM Helper's store, `Data/MCM/Settings/MFO.ini`, is read after it and wins, so a setting you change in the MCM overrides the value here. The MCM store is created on first launch from `MCM/Config/MFO/settings.ini` and is never shipped in the zip, so updating MFO does not reset your MCM settings.

Deleting the file or any line is safe: MFO falls back to the same compiled default. `1` is on and `0` is off unless a key says otherwise. A key whose meaning changes is renamed, never redefined.

## [Detection]

MFO seed defaults. MCM Helper's Data/MCM/Settings/MFO.ini is read AFTER this and wins. A key whose MEANING changes must be RENAMED, never redefined -- MCM Helper persists by key name into MO2 overwrite and stale values survive mod updates (INVARIANTS #37).

- **`bAllowSummons`** (default `0`).

## [Rapport]

- **`fRapportRate`** (default `2.0`).
- **`fRapportKill`** (default `1.0`).
- **`fRapportBossMult`** (default `5.0`).
- **`fRapportDragonMult`** (default `10.0`).
- **`fSharedRadius`** (default `3000.0`).
- **`fSharedCombatGrace`** (default `15.0`). Seconds after a follower was last SEEN fighting that they still count as having shared a kill. Killing the last enemy ends combat, so the fight is already over by the time a death is processed -- without this, a follower who fought the whole battle away from the player earns nothing.
- **`iBossLevelDelta`** (default `5`). A kill counts as a boss if the actor is UNIQUE (named one-off) or is at least this many levels above you. IsUnique alone missed generic dungeon bosses -- a bandit chief has a boss bar but is not a unique actor.
- **`iRapportRank2`** (default `250`).
- **`iRapportRank3`** (default `1000`).
- **`iRapportRank4`** (default `2500`).
- **`iRapportRank5`** (default `5000`).
- **`bRapportToasts`** (default `1`). One HUD line when a follower's rapport RANK rises ("Lydia fights beside you with new resolve."). Rank changes are rare by design, so this cannot spam.

## [Progression]

- **`bSharedGrowth`** (default `1`). PROGRESSION ADDON (needs MFO_Progression.esl; sections are cosmetic to the parser). Shared Growth: 1 = benched enrolled followers level at the addon's divisor rate (half by default -- the roster-strategy price); 0 = everyone matches the player's level at full rate. A PLAYER setting (later an MCM Addons toggle); the economy numbers themselves live in the ESL for xEdit.

## [UI]

- **`bShowHud`** (default `0`). Passive top-right readout. Draws every frame, takes no input, so it stays usable while fighting. This is the primary observation surface.
- **`iBoardKey`** (default `-1`). DIK code (DECIMAL) for a key that opens and closes the Field Orders board, the same as casting the Field Orders power. -1 = unbound (default). Also set in the MCM, Interface page. Pick a key the game does not use, for example 26 = [ or 27 = ].
- **`iHudKey`** (default `-1`). DIK code (DECIMAL) for a key that toggles the combat HUD readout. -1 = unbound (default). Also set in the MCM, Interface page.

## [Targeting]

- **`bCommandTarget`** (default `1`). Installs a vfunc hook on Character::UpdateCombat so MFO can command WHICH foe a follower fights. OFF until measured. NOTE: turning this ON needs a restart (the hook installs once at load); turning it OFF works live.

## [Evaluator]

- **`bSeedEvaluatorRules`** (default `0`). Seeds "Self HP < 40% -> Cast Healing" + "Always -> Wait" onto each follower, so gambits are testable before the board exists. OFF for real play.
- **`bEquipToCast`** (default `1`). Put the gambit spell in the follower's hand and let their OWN AI cast it -- the only path that can animate. OFF by default: it moves real equipment.
- **`fAiCastGrace`** (default `3.0`). Seconds to wait, after equipping, for their AI to cast before MFO does it silently instead. Zero destroys the very thing this is meant to measure.
- **`bDriveCaster`** (default `0`). Minimum seconds between gambit casts for one follower. THE RATE LIMITER -- a cast takes the spell out of their hand and this decides when it returns, because a follower can only cast what they are holding. Not a resource cap: a weak heal SHOULD be cast many times in a long fight. Probe: drive the caster state machine instead of applying the effect.
- **`bProbeCastStyle`** (default `0`). P1 PROBE, DEV-ONLY, DEFAULT OFF -- carries CTD risk; leave at 0 unless you are running the combat-style experiment. While a cast rule is latched, swap the follower's live per-combat style to MFO_CastStyle (caster-forward: high magic score, low melee) and restore on release, to measure whether his own AI casts more (and stays mobile). Watch "[probe cstyle]" in MFO.log. Needs a full game restart to arm. Not exposed in the MCM on purpose.
- **`bWeaponStyleControl`** (default `1`). WEAPON-STANCE OWNERSHIP -- STANDARD FEATURE, DEFAULT ON. When an equip gambit wins a follower's hand, swap their live per-combat combat style to MFO_MeleeStyle / MFO_RangedStyle so the engine stops re-drawing the weapon MFO didn't pick (the bow<->mace ping-pong an archer's own AI causes). Reverts at battle end. This is a debug kill-switch only -- set to 0 to disable. Watch "[wstyle]" in MFO.log. Not in the MCM on purpose (it is expected behaviour).
- **`bCstyReassert`** (default `1`). CSTY RE-ASSERT A/B PROOF TOGGLE -- DEFAULT ON (today's behavior, byte- identical). When the engine re-derives a follower's combat style away from MFO's owned stance mid-combat, MFO normally re-asserts it EVERY TICK -- the suspected cause of combat-only, intermittent positioning stutter (see Docs/SPEC-COMBATSTYLE-SOURCEGATE.md). Set to 0 to stop re-asserting: the one-shot stance set when MFO first takes the controller stands, and the existing equip gate is relied on to hold the weapon instead. Flip live mid-battle with Numpad 7 (iCstyReassertKey) for an A/B without a restart. Watch "[wstyle]" in MFO.log.
- **`iCstyReassertKey`** (default `71`). DIK code for the bCstyReassert live-flip hotkey. 0x47 (71) = Numpad 7, unbound in vanilla. 0 disables the hotkey (INI-edit + reload still works).
- **`bFriendlyFireHold`** (default `1`). FRIENDLY-FIRE HOLD -- DEFAULT ON. Hold a follower's OFFENSIVE cast when one of your own teammates is in the AoE blast or on the caster->target line (the engine's line-of-sight passes through allies, so a mage would otherwise fire into a teammate's back in a hallway). Set to 0 to let followers fire freely. Watch "[consent] ... HARD-ABORTED cast of ... (friendly fire)" in MFO.log.
- **`bQuashAllyCombat`** (default `1`). QUASH ALLY COMBAT -- DEFAULT ON. Followers must never fight each other. If one follower aggros another (usually friendly fire), MFO ends that combat on both sides. Set to 0 to disable. Watch "[peace]" in MFO.log.
- **`bCastSelf`** (default `1`). SELF / AUTO CASTING -- DEFAULT ON (v1.0.65). Lets a follower cast a beneficial spell on himself and, via "Cast on target" set to Auto, on the whole party: self-buffs/lights (Candlelight), heals to injured allies, and hostile spells onto nearby enemies. Effect + magicka only, no animation (deferred). Set to 0 to leave all casting to the follower's own AI. Watch "[cast] ... AUTO ..." and "[cast] ... SELF-CAST ..." in MFO.log.
- **`fCastCooldown`** (default `4.0`).
- **`fDotRecastBurstRatio`** (default `1.0`). AUTO fan-out: how eagerly a HOSTILE duration spell (a DoT/debuff) is re-cast on a foe it is already ticking on. MFO splits the spell into up-front BURST damage and per-second DOT, then recasts only when burst >= dotRate * (DoT time remaining) * fDotRecastBurstRatio. 1.0 = recast once the burst outweighs the DoT still to be delivered; raise it to let the tail run longer, lower it to recast more eagerly. Pure-burst spells always fire; pure-DoT spells wait out their duration.
- **`fBeneficialRecastFrac`** (default `0.85`). AUTO fan-out: how a BENEFICIAL DURATION buff (Candlelight/Magelight and other lights, wards, fortifies) is kept from re-casting on a robotic, too-fast beat. A light applied hands-free never registers as "already active", so without this MFO respammed it every couple of seconds while magicka lasted. MFO now waits until the buff is near its own real expiry before re-casting: window = (buff authored duration) * fBeneficialRecastFrac * (1 +/- jitter), jitter uniform in [-fBeneficialRecastJitter, +fBeneficialRecastJitter]. 0.85 re-casts at ~85% of the buff's life (a small safety margin so it never lapses); the +/-20% jitter makes each recast delay a little different so it looks human. INSTANT beneficial spells (instant heals) are exempt and re-fire on demand; concentration streams (Healing Hands) are exempt too. Watch "[cast] ... beneficial recast suppressed" in MFO.log.
- **`fBeneficialRecastJitter`** (default `0.20`).
- **`fMagickaReserve`** (default `0.0`). Fraction of magicka a gambit will not leave them below AFTER a cast. OFF by default on purpose -- a follower healing to stay alive is exactly who a floor gets killed.
- **`bCommandCast`** (default `0`). Probe only. DoCombatSpellApply is an instant SILENT apply, not an animated cast -- kept solely to measure whether it deducts magicka.
- **`fSuppressWindow`** (default `1.5`). Seconds a follower stays quiet after a real action fires.
- **`iCastSource`** (default `3`). Which caster a gambit spell uses. 3 = kInstant applies the effect but plays NO animation (proven). 1 = right hand is the candidate for a visible cast. 0 = left hand, 2 = other. Use the Probe tab to find which animates. PROVEN 2026-07-21: NO source animates. Left at 3 (kInstant) because the hand sources buy nothing and kInstant is the honest name for what happens.

## [Debug]

- **`bProgProbe`** (default `0`). FOLLOWER-PROGRESSION SINKER PROBE -- DEV-ONLY, DEFAULT OFF, LOG-ONLY OUTPUT. Arms the throwaway probe for the progression ESL design (P1 perk-on-NPC / P2 base-AV survival / P3 reapply idempotency). When armed, pressing the probe key adds ONE real perk from the load order's own perk trees to your CURRENT follower's base (SPID pattern) and writes a known +10 OneHanded base-skill allocation to them. Everything is reported under "[prog]" in MFO.log. First press = full probe; later presses = status re-read (press again after levelling up); save+reload = the P3 reapply check runs by itself. Use a throwaway save: the perk/skill changes are real (though log-only in intent) and the skill write persists into saves taken afterwards.
- **`bAttackObserve`** (default `0`). PASSIVE ATTACK-EVENT PROBE -- DEV-ONLY, DEFAULT OFF, LOG-ONLY. Counts every attack move a follower's own animation graph reports during a fight (attackStart, power attacks, bashes, MCO / BFCO / SCAR / Payload Interpreter / Parkour tags) and prints one "[atk-obs]" histogram line per follower per fight, with how long he stood in reach of his target with weapons drawn and not attacking. Sends nothing to the game. 1 = on (the Deck test INI sets 1 for the 2026-09-21 cycle). Watch "[atk-obs]" in MFO.log.
- **`bHeartbeat`** (default `1`). HEARTBEAT -- DEFAULT ON, LOG-ONLY, one line every 5 seconds. Prints "[hb] worker ticks=N main drains=M ..." from MFO's own sleeper thread, so a freeze shows which thread stopped: worker ticks stop = the SKSE task worker hung, main drains stop = the game's main thread hung. 0 = off.
- **`iProgProbeKey`** (default `39`). DIK code for the probe trigger key, in DECIMAL (the parser is base-10 only). 39 = DIK 0x27 = semicolon, unbound in vanilla. 0 disables the trigger.
- **`bProgCatalogDump`** (default `0`). PROGRESSION CATALOG DUMP -- DEV-ONLY, DEFAULT OFF, READ-ONLY. Forces the production catalog reader (progression addon component 1) to build at load even without MFO_Progression.esl, and dumps the full [prog] census to MFO.log: per skill tree, kept/marginal/filtered perk counts, every filtered perk with the reason it was filtered, and spot-check nodes (grid/dome coords + skill-req strings). Mutates nothing -- no perk, no skill, no save. Needs a restart.
- **`bProgHarness`** (default `0`). PROGRESSION ALLOCATOR DEV HARNESS (addon component 2) -- DEV-ONLY, DEFAULT OFF. Needs MFO_Progression.esl enabled (the allocator is inert without it). When armed, the harness key runs ONE allocator verb on your current follower; pick the verb from the console first:  set MFOP_DevCmd to N 0=status  1=enroll  2=cycle class (Melee/Ranged/Mage)  3=dump auto-scaled skills  4=allocate next eligible perk (full gating)  5=respec (-500 rapport) 6=economy dump.  Everything reports under "[prog]" in MFO.log. Use a throwaway save: enrollment/class/perk state serializes into the co-save and the perk/skill writes on the follower are real.
- **`iProgHarnessKey`** (default `40`). DIK code for the harness trigger key, in DECIMAL (the parser is base-10 only). 40 = DIK 0x28 = apostrophe, unbound in vanilla. 0 disables the trigger.
- **`bEnableLogging`** (default `1`).
- **`bLegacyCastHybrid`** (default `0`). INI-only: read from `SKSE/Plugins/MFO.ini` ONLY, there is no MCM control (a value in the MCM store is ignored). `1` makes casts use the ORIGINAL AI-first-grace + force-on-miss package hybrid even with Harbinger present; with Harbinger absent that path runs automatically. See `Docs/CAST-DELIVERY.md`.
- **`bProfileEvaluator`** (default `0`).
- **`bSeedTestData`** (default `0`). Writes synthetic gambits onto a player-keyed record. Only meaningful if you intend to SAVE with the mod active. Off = MFO leaves nothing behind at all.
- **`bCasterHook`** (default `1`). The influence actuator: remove the AI's veto on casting a gambit spell so the follower casts it themselves, mobile. Installs a vfunc hook.
- **`iCasterMode`** (default `1`). 0 = log only (observe the AI's answer), 1 = force (override a veto).
- **`bForceCastOnMiss`** (default `1`). HYBRID FORCED CAST (v1.0.27): if the follower's own AI casts a DIFFERENT spell (or nothing) during the grace window, force the gambit's configured spell through the cast package at the chosen target -- line of sight required for the forced shot. 0 = old behaviour (AI decides, silent fallback).
- **`bUsePackages`** (default `1`). The package-actuation machinery the forced cast rides (MFO_CommandQuest alias 0 + MFO_CastPackage). ON since v1.0.27; release is by marker eviction with a load sweep, so a mid-cast save self-heals.
- **`bWarnNoApmf`** (default `1`). MFO works best with Harbinger (APMF) installed and runs its full legacy fallback without it. 1 (default) = show one unobtrusive corner-toast reminder every ~10 minutes while APMF is absent; 0 = never show it. Has no effect at all when APMF IS installed (the toast never fires either way).
- **`bApmfEquipAuthority`** (default `1`). Harbinger (APMF) EQUIP AUTHORITY. 1 (default) = MFO declares each follower's worn set to Harbinger, which equips it and refuses every other engine equip on that follower (the AI putting a shield back on a dual wielder, outfit re-apply, RemoveItem re-equip). 0 = MFO equips gear directly as before. Inert without Harbinger at ABI v9 or newer. Harbinger's own [EquipAuthority] bEquipObserveOnly decides whether refusals are enforced or only logged.
- **`bWeighWeapons`** (default `0`). EXPERIMENTAL, parked for batch D. 0 = MFO equips weapons, shields and torches itself, as before weighting existed. 1 = with Harbinger at ABI v22 or newer, MFO stops those direct equips and asks Harbinger to place them (ch.17 one-shot placements) and prefer them (ch.26). INI only, not in the MCM. Turning it off mid-session releases every ch.26 claim and drops pending placements on the next MCM close. Armor is never weighted.
- **`bHealAnimPackage`** (default `1`). Animated heals in combat. 1 (default) = with Harbinger installed and the follower in combat, a heal gambit (self, an ally, the player, or Auto) is cast by the follower's own AI with the real hand animation, one cast at a time, lowest health first. Out of combat heals land instantly (no animation yet). 0 = kill switch: every heal lands instantly, no cast animation. Wholly inert without Harbinger.
- **`bLogistics`** (default `1`). ── Logistics (M6): a non-combat rule table -- drink potions, loot arrows/ potions/gear. OFF by default; reviewed but young.
- **`fFirstDibsDelay`** (default `4.0`). Seconds a follower waits before looting an item, giving the player first dibs.
- **`fQuickLootWaiver`** (default `4.0`). Collapsed delay once the player has looted from that source (QuickLoot). Never 0.
- **`fChanceRadius`** (default `512.0        ; player "had a chance" within this of the source`). ── Claim-and-Release loot priority (dibs). The follower may take a value-tier from a source only once the PLAYER's claim on it releases -- by evidence about the player, not a wall clock. fFirstDibsDelay above = the Gear anti-snatch grace; fQuickLootWaiver = the post-take Rejection linger.
- **`fFairChance`** (default `6.0            ; seconds near + facing/considering before Valuables release`).
- **`fAbandonDelay`** (default `45.0         ; player never came near -> Valuables release after this`).
- **`fDepartRadius`** (default `700.0        ; player took, then left this far -> "moved on"`).
- **`fPlayerBubble`** (default `150.0        ; convergence yield: never walk to loot within this of you (arrows/bolts/lockpicks exempt)`).
- **`fValuablesRatio`** (default `20.0`). Loot valuables (to sell): a MISC item qualifies when its gold/weight ratio clears this. 20 puts raw gemstones and similar high-density loot in.
- **`fLootRadius`** (default `3000.0`). How far (game units) a follower scans for loot. ~70 units = 1m; a cell = 4096. 3000 ~= 4-5 rooms. Candidates must also be within the confidence leash of you.
- **`bLootTravel`** (default `1`). OPTION A: follower WALKS to loot instead of teleport-grabbing. On by default (reworked in v0.8.2 -- native release + walkable radius). Set 0 to disable.
- **`bLootTravelViaApmfTravel`** (default `1`). A/B TEST SWITCH -- which ROAD a loot excursion walks on. Needs APMF (Harbinger) v0.9.5 or newer; wholly inert without it. 0 = MFO's own road: MFO points its OWN travel package (MFO_APMFLootTravelPackage0-3) and offers it through APMF's package-offer channel. 1 (default) = MFO claims APMF's ch.19 travel facet and names the loot item as the destination, and APMF points its own package (Data/APMF.esl) and ends the leg on arrival or on combat. Both roads work; flipping this mid-session is safe (a walk already in progress finishes on the road it started). Grep "[loot-road]" in MFO.log to see which road each dispatch took, and APMF.log's "[travel-leg]" lines for road 2's APMF side.
- **`bLootInPlayerHomes`** (default `0`). Loot inside PLAYER HOMES. 0 (default) = never loot in your own house (any cell flagged LocTypePlayerHouse); 1 = loot there too. Drinking/supply is unaffected.
- **`bLootSpecialItems`** (default `1`). Loot artifacts + sell socketed gear. 1 (default) = followers loot artifact/ unique-item exclusions, AND sell their MEO-socketed gear instead of hoarding it unsold (gems extracted+kept first when your gem-mod supports it, else sold as-is); 0 = both protected (never looted / socketed gear never sold). Worn artifacts are never stripped off a follower either way. Quest items always stay engine-protected regardless.
- **`bLootLOTD`** (default `0`). LOTD awareness (Legacy of the Dragonborn). 0 (default) = off. 1 = followers know what the museum still needs: the "Loot museum items" gambit appears on the board, a follower never sells a relic the museum needs, and a follower with that gambit carries what he finds to a nearby Museum Shipments crate. Turning it on shows LOTD's own shipping intro once. Does nothing without LOTD (the MCM hides it).
- **`bEconomy`** (default `1`). Follower economy: 1 (default) = sell junk + buy supplies at merchants; 0 = dry-run log only.
- **`bEconomyBuyGear`** (default `1`). Economy sub-toggles (both gated under bEconomy). 1 (default) each. bEconomyBuyGear: buy ONE best-affordable weapon/armor/mage-apparel upgrade per visit, only when it costs <= 50% of the follower's purse (keeps a reserve).
- **`bEconomyBuyTomes`** (default `1`). bEconomyBuyTomes: a MAGE follower (has a cast gambit) buys spell tomes for its top-2 magic schools it does not know yet, then studies them. Auto-learning a tome you HAND a mage is independent of this toggle; this only gates buying.
- **`bTownToasts`** (default `0`). One HUD corner line when a follower begins trading at a shop: "Auri is trading with Niranye." One line per errand, never per tick, no amounts and no failure notices. Only matters while `bTownErrands` is on.
- **`iErrandGait`** (default `2`, MCM "Economy: town errand walking speed"). The walk speed of a town errand, separate from the loot walk (`iTravelGait`): 0 = Walk, 1 = Jog, 2 = Run, the same scale. Sent to Harbinger as the errand walk's travel speed bits. Default = the loot walk's default, so nothing changes until it is set.
- **`bProximityTrading`** (default `0`, INI-only, no MCM control). The pre-town proximity trade: 1 = a follower that merely stands near a vendor (and is not on an errand) sells and buys on the spot, as before town errands existed. 0 = followers trade only on a town errand. Gates only `Service.cpp`'s call into the instant probe; town errand trades follow `bEconomy` / `bTownErrands` exactly as before. With Harbinger absent and this at 0 there is no instant trade. One `[config] bProximityTrading = N` line is logged at every config read.
- **`bFollowerCatchUp`** (default `1`, INI-only). About 3 s after a fast travel / load door / teleport, a follower the engine left behind (not in your cell, or more than 4096 units away outdoors) is moved to you. Never moves one told to wait, dismissed, in combat, MFO-off, or on a town errand. `0` = off.
- **`bTownErrands`** (default `1`). TOWN ERRANDS (R1a, Harbinger ABI 24+): with Harbinger present a follower no longer trades instantly with any vendor near him. When you are in a City / Town / Settlement and he has junk to sell, a supply to restock or an affordable upgrade, he walks to an open shop's vendor, plays the talk / give / take animations, trades and rejoins. Needs `bEconomy`. `0` = the old instant proximity trade. Harbinger absent or older than ABI 24: the old trade is always used.
- **`iErrandMinSellGold`** (default `100`). A sell errand needs the junk a vendor accepts to be worth at least this much (capped by that chest's last-seen gold).
- **`iErrandMinPurse`** (default `200`). The purse an upgrade errand (gear, apparel, tome) needs before the walk is worth it.
- **`fErrandSettleSec`** (default `10`). Seconds you must have been in the town before anyone goes shopping.
- **`fErrandCooldownSec`** (default `120`). Real seconds between one follower's errands.
- **`fErrandMaxGameMin`** (default `120`). An errand older than this many GAME minutes ends and the follower rejoins.
- **`fErrandTradeRealSec`** (default `8`, 1-120). REAL seconds an OFF-SCREEN errand spends at the vendor, scaled by the live timescale onto the game clock (about the on-screen trade). The walk there and back is distance / 150 u/s in real seconds (floor about 2 s), scaled the same way.
- **`iErrandTradeGameMin`** (legacy). Still read so an old INI parses, no longer used (replaced by `fErrandTradeRealSec`).
- **`bErrandSmith`** (default `1`). SMITHING ERRANDS (town phase 2 R8). A follower whose worn weapon or armor piece his Smithing (plus his tempering perks) can improve takes it into his town trip: he buys the improve recipe's materials at a smith or general shop regardless of his gambits, then does the work at the town's sharpening wheel (weapons) or armor table (armor). The result is the engine's own temper formula. `0` = no smithing errand and no material wishes.
- **`iSmithWorkGameMin`** (default `20`). Game minutes the smithing work takes at the station (off screen: the time cost of the simulated stage).
- **`bErrandSmithFurniture`** (default `1`). `1` = ask Harbinger to play the station's furniture animation while he works; `0` = work without it. If Harbinger refuses or the furniture is not entered, the work still happens and the log says so.
- **`bErrandInn`** (default `1`). TOWN PHASE 2 (inn + temple). The inn is the LAST stop of every town trip: the follower buys a small food stock from the innkeeper, eats a meal, and STAYS at the inn (sitting, resting, sleeping at night when a bed he may use is free) until you leave the town, or combat starts. Before the inn he visits the town's temple when he is diseased or has not been blessed this game day. Needs `bTownErrands`. One trip per town visit: once it ends no new errand is planned for him until you leave town.
- **`iInnMeals`** (default `1`). Meals he eats at the inn.
- **`iInnFoodStock`** (default `3`). Food items he carries after the inn (bought at the innkeeper, best by value of the food's own effects).
- **`iTempleGameMin`** (default `10`). Game minutes an OFF-SCREEN temple visit takes (the blessing is owed and paid when he is next loaded at the shrine).
- **`bHmsRedistribute`** (default `1`). CLASS HMS ON LEVEL-UP (v1.0.68). bHmsRedistribute: 1 (default) = each level a follower's Health/Magicka/Stamina gain is reshaped to its class profile (mage -> Magicka, archer -> Stamina, warrior -> Health); total gain == vanilla, only the split changes. 0 = vanilla per-level HMS stands untouched.
- **`fHmsSkewMax`** (default `20.0`). fHmsSkewMax: skew ceiling as a PERCENT of each level's HMS budget that may be pulled from the class-primary pool toward an off-class pool the follower actually exercises in battle (a battle-mage earning some Magicka). 0 disables.
- **`bMageWearRobes`** (default `1`). MAGE DRESS-UP (loot + buy). bMageWearRobes: 1 (default) = a caster wears mage clothing/jewelry; 0 = a caster picks/buys real ARMOR by rating like any class.
- **`bMageApparelStrictSchool`** (default `0`). bMageApparelStrictSchool: 0 (default) = value-driven (wear the most expensive piece); 1 = an ENCHANTED apparel piece must fortify one of the follower's top-2 magic schools (plain clothing/jewelry unaffected, so no slot is left bare).
- **`bMeoAwareGems`** (default `0`). MEO AWARE FOLLOWERS (needs MEO). bMeoAwareGems: 0 (default) = followers still CONSERVE gems (a gem pulled off gemmed junk before selling is re-socketed into their own worn gear, never left loose -- always on with MEO); 1 = followers also OPTIMIZE, choosing the best gem per empty socket and swapping up to stronger gems.
- **`bSpeechPricing`** (default `1`). SELL PRICING + MERCHANT-PERK BYPASS (advanced; INI-only, no MCM). Gated under bEconomy. bSpeechPricing: 1 (default) = the follower's OWN barter prices (town phase 2 R2): his Speech and his kModBuyPrices / kModSellPrices perks drive BOTH what he pays (buy) and what he is paid (sell), using the real GMSTs (fBarterMax/Min, fBarterBuyMin, fBarterSellMax, fMinBuyMult, fMaxSellMult) read at runtime; perks are evaluated while he is loaded and cached (60 s window) per vendor, an unloaded follower with no cached value uses the Speech-only factor and the log says so; 0 = base value both ways.
- **`bMerchantPerkBypass`** (default `1`). bMerchantPerkBypass: 1 (default) = a follower holding the merchant perk (xMerchantPerkID) may SELL items outside the vendor's normal buy filter, like the player; 0 = vendor filter only.
- **`xMerchantPerkID`** (default `0x00058F7A`). xMerchantPerkID: the "sell anything" perk FormID (hex ok). 0x00058F7A = vanilla Merchant (this modlist's Ordinator "Salesman"). Change if your perk overhaul uses a different perk.
- **`iFencePerkID`** (default `0x00058F79`). iFencePerkID: the perk a follower must own before a town errand visits a FENCE (a vendor faction that buys only stolen goods; hex ok). 0x00058F79 = vanilla "fence" (Skyrim.esm). The fence's own vendor conditions must ALSO pass (e.g. Tonilia needs the Thieves Guild stage, evaluated against the player). Stolen goods are sold ONLY to a fence, never to a normal vendor. Change if your perk overhaul uses a different perk.
- **`bAutoRetreat`** (default `0`). AUTO-RETREAT: 0 (default, off while retreat is reworked) ; 1 = a badly-outmatched follower (low confidence) far from you in combat falls back to your side. Fires once per fight; the follower stops gambitting while falling back. The confidence leash taken to its conclusion. Anniversary Edition only (like walk-to-loot); no-op on Special Edition 1.5.97.
- **`bEngageOnSight`** (default `0`). ENGAGE ON SIGHT: 0 (default) = off. 1 = the hidden out-of-combat gambit "nearest visible enemy": while the party is out of combat (looting included), a follower who SEES a foe (line of sight) within the leash from you enters combat against the nearest one. Needs Harbinger (APMF) 0.9.9 or newer (ABI 14). Without it this does nothing. Runs with or without auto-retreat (changed in 2.3.0). A foe is anything the game says is hostile to you or the follower, anything territorial (an Aggression 0 creature with an aggro radius, like Requiem wolves, skeevers and bears) or anything already fighting the party. Cowardly (Confidence 0) creatures and crime-faction townsfolk and guards are never engaged unless they are fighting the party. Every skipped nearby actor is logged with the reason, at most once per 30 seconds each.
- **`sEngageOnSightSkip`** (default giants, mammoths, carriage drivers, ferrymen, castle and palace servants, merchants, townsfolk of the generic crime faction, prisoners and Blackreach servants). Comma-separated factions or races that Engage on Sight never treats as territorial foes. The skip list only affects territorial creatures: anything the game already treats as hostile is engaged. Each entry is `Plugin.esp|0xLOCALFORMID` or an EditorID. Read once at start, so a change needs a restart. An entry for a plugin that is not installed is ignored and noted in the log.
- **`bEngageOnSightSneaking`** (default `0`). bEngageOnSightSneaking: 0 (default) = engage on sight does NOT fire while you sneak. 1 = it fires while you sneak too.
- **`fEngageOnSightRange`** (default `2000.0`). fEngageOnSightRange: the farthest (game units, from the FOLLOWER) a follower will spot and charge an enemy for engage on sight. Default 2000 (~29 m), range 500-4000. The leash from you still caps it.
- **`bMagicLoadout`** (default `1`). MAGIC LOADOUT: 1 (default) = a follower with cast gambits (a magic user) loots school-appropriate enchanted apparel -- robes/hoods/gloves/boots boosting his most-cast school beat raw armor rating on those slots (school match first, then fanciness: gold value + fortify strength) -- and keeps ONE one-handed melee backup for when his magicka runs out. 0 = the old rating-only looting.
- **`bMageDaggersOnly`** (default `1`). 1 (default) = the mage backup is DAGGERS only (a caster's sidearm). 0 = the best of any one-handed weapon.
- **`bBeastHeadFix`** (default `1`). BEAST-RACE HEAD FIX: 1 (default) = after equipping looted gear on a beast-race follower (Khajiit/Argonian, incl. custom ones like Inigo), force a 3D rebuild so their HEAD reattaches -- beast heads go invisible on a scripted equip otherwise. Beast-gated (human followers are untouched). 0 = disable (e.g. if the 1-frame rebuild is visually distracting). Watch "[beasthead]" in MFO.log.
- **`iMinPotionMag`** (default `0`). LOW-POWER POTION FLOOR: a restore potion below this magnitude is ignored entirely; the rest are looted strongest-first. 0 = AUTO (use the load order's weakest restore tier, logged as [potfloor] at startup). A positive value is an explicit floor across all restore types. Fortify/cure potions are never filtered.
- **`fTravelRadius`** (default `4096.0`). HARD CEILING on walk-to-loot distance. The real limit is the confidence leash (walkLimit = min(leash, this)); lower this only to clamp BELOW the leash.
- **`fBatchLinger`** (default `1.5`). BATCH EXCURSION: a follower stays out and loots multiple corpses in one trip (retargeting closest-first) instead of returning to you after each one. fBatchLinger: when loot is nearby but still under YOUR dibs, wait this long (re-scanning) before giving up and returning. 0 = never wait (exhaust & return).
- **`fExcursionMax`** (default `60.0`). fExcursionMax: whole-excursion hard cap (seconds) -- he returns after this no matter what, so a batch can't run away. The leash still bounds how far he roams.
- **`fNavmeshGate`** (default `300.0`). NAVMESH GATE (units): before walking to loot, MFO checks the nearest navmesh point to the body; farther than this = off the navmesh (unreachable) -> skip it before he freezes. ~300. Raise if reachable bodies get skipped, lower if he still walks to unreachable ones. 0 disables the gate.
- **`fLeashMin`** (default `512.0`). The confidence leash: how far from YOU a follower will range, scaled by how safe they feel (health/resources, less in a fight). Min ~= one room (scared), max several rooms (confident). Units: ~70/m, cell 4096.
- **`fLeashMax`** (default `4000.0`).
- **`fHealApproachRadius`** (default `384.0`). HELD-HEAL APPROACH (Harbinger ch.24, needs APMF with ABI 19): when a follower's heal is held behind a wall (no line of sight to the recipient), he walks toward the recipient in his combat gait until within this many units, still fighting with the other hand. Range 64..2048. Default 384 = about half a room.

## [Taunt]

- **`fTauntDuration`** (default `15.0`, MCM slider 5 to 60). How long, in seconds of running game, a foe that rolled a hit stays pinned onto the taunter before it picks its own target again. It is released sooner if the taunter goes down or dies, the foe dies or unloads, the fight ends, a save loads, or Harbinger ends the hold itself.
- **`fTauntRadius`** (default `1024.0`, range 256 to 2048). Plain INI, not in the MCM. How far from the taunter, in game units, an extra foe may be and still roll. The foe the gambit chose is exempt.
- **`iTauntMaxFoes`** (default `4`, range 1 to 6). Plain INI, not in the MCM. Foes per taunt, counting the one the gambit chose. 4 means the chosen foe plus up to 3.

- **`bTauntProbe`** (default `0`). Dev only, plain INI, not in the MCM. 1 = write rate-limited `[taunt-probe]` lines to MFO.log. P1 says whether the combat taunt idle would play for a follower in combat right now (every 5 s per follower) and names the first failing condition record. P2 says whether each follower is held, lost or absent in the combat group of each foe that is fighting the party, how often that foe switches target, and whether it senses the follower (every 2 s per follower). It logs only. No claim, no animation, no change to the game. P2's SenseActor call is not zero-impact on Harbinger: it costs up to 3 synchronous rays on the main thread, shares the `kLosMaxSyncPairsPerFrame` budget of 8, and registers pair interest that Harbinger re-measures every 250 ms for 2 s.
