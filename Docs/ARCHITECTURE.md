# MFO — Architecture

The subsystem map, thread/lock model, hook inventory, and the
generator↔DLL contracts. Read this before touching `native/plugin.cpp`.

**STATUS: planned, not built.** The sibling ARCHITECTURE docs carry `file:line`
refs into shipped code; this one cannot yet. **Every line ref below is a
placeholder to be filled as the code lands** — a ref that says `(P2)` means
"this subsystem arrives in phase P2." Anything here that survives contact
with the compiler unchanged was lucky, not correct.

The living truth for behavior will be `native/plugin.cpp` and its siblings.
When this document and the code disagree, the code is right and this document
is a bug.

---

## 1. Module layout

MEO and MAO each ship a single `plugin.cpp` (MEO's is ~7,000 lines). **MFO
deliberately splits**, because its subsystems have sharply different change
rates and one of them — the evaluator — is a hot path that benefits from
being readable in isolation:

```
native/
  plugin.cpp        SKSEPluginLoad, messaging, sink registration, startup.
                    The only file that knows about load order of subsystems.
  Scheduler.cpp/h   Frame clock, tick decision, round-robin service order,
                    jitter. No engine reads beyond time. (P2)
  Evaluator.cpp/h   Snapshot build, top-down rule scan, first-match. The hot
                    path. No mutation, ever. Serves BOTH tables -- one scan
                    routine, two rule lists, chosen by combat state. (M5)
  Logistics.cpp/h   The non-combat table's own conditions and actions: supply
                    checks, loot eligibility (ownership, first-dibs delay and
                    waiver), category/metric equipment comparison. (M6)
  Actuation.cpp/h   Tier A/B action execution. The only file allowed to
                    mutate actor state. (P2)
  Vocabulary.h      GENERATED by tools/gen_vocab_header.py. constexpr
                    condition/action tables. Never hand-edited. (P2)
  Followers.cpp/h   Registry: detection, ActorHandle management, per-actor
                    authoritative state. (P1)
  Rapport.cpp/h     Income, thresholds, rank derivation. (P1)
  Ledgers.cpp/h     Package overrides: apply, release, reconcile-on-load.
                    (Tutored spells are OUT OF SCOPE -- DESIGN 5.4.) (M9)
  Serialization.cpp/h  Co-save read/write/revert, schema versions. (P0)
  Board/            The ImGui board — lifted from MEO, re-skinned. (P3)
    BoardHooks.cpp    D3DInit / DXGIPresent / InputDispatch / WndProc
    BoardDraw.cpp     Layout, rows, skins
    BoardInput.cpp    Key translation, gamepad, stick edge-trigger
  Config.cpp/h      INI + MCM Helper parse, live re-read. (P1)
  PCH.h
```

`add_commonlibsse_plugin(... SOURCES ...)` takes a list; the split costs
nothing in the build. **Do not let this become a dozen files** — the sibling
convention exists because cross-file indirection in engine code makes crash
logs harder to read, and that cost is real.

## 2. Subsystem map

| Subsystem | Owns | Phase |
|---|---|---|
| **Startup** | Form resolution, power grant, sink registration, ledger reconcile | P0 |
| **Serialization** | Co-save schema, `ResolveFormID`, migration, revert | P0 |
| **Followers** | Who is eligible, `ActorHandle` lifetime, authoritative per-actor state | P1 |
| **Rapport** | Income from death/combat events, thresholds, rank | P1 |
| **Config** | INI + MCM parse, live re-read, clamping | P1 |
| **Scheduler** | Frame clock, tick cadence, service order, jitter | P2 |
| **Evaluator** | Snapshot, rule scan, first-match selection — for both tables | M5 |
| **Logistics** | Supply conditions, loot eligibility, first-dibs timing, equipment comparison | M6 |
| **Actuation** | Executing the selected action; suppression state | P2 |
| **Vocabulary** | Compiled condition table + per-actor derived action set | P2 |
| **Board** | ImGui menu, snapshot for render thread, edit actions | P3 |
| **Ledgers** | Package overrides: apply, release, reconcile | M9 |

**The dependency rule:** Evaluator reads; Actuation writes; nothing else
mutates actor state. A predicate that mutates is a bug even if it works
(§INVARIANTS #12).

**The two tables share the evaluator, not the schedule.** One scan routine
serves both; which list it runs against is decided by the follower's combat
state, and they never interleave (`DESIGN.md` §4.8). Logistics owns only its
own vocabulary and its eligibility rules — the loot delay, the player-take
waiver, the ownership bar — not a second scanner.

## 3. Thread and lock map

Four threads touch MFO state. This section is the whole concurrency design;
if a change does not fit here, the change is wrong.

| Thread | Enters via | May do |
|---|---|---|
| **Main** | SKSE task interface, event sinks, serialization callbacks | **Everything.** All engine reads and all engine mutation. |
| **Render** | DXGI present hook | Increment the frame clock; draw the board from a snapshot. **No engine reads, no mutation.** |
| **Input** | Input dispatch hook | Push ImGui IO events; set `wantClose`. Nothing else. |
| **Window** | WndProc | Clear ImGui keys on `WM_KILLFOCUS`. Nothing else. |

### 3.1 Shared state

| State | Type | Written by | Read by | Guard |
|---|---|---|---|---|
| `g_followers` — authoritative per-actor state (gambits, rapport, ledgers) | map | Main | Main | **NONE — single-threaded by construction** |
| `g_frameCount`, `g_frameDeltaMs` | atomics | Render | Main | lock-free |
| `g_board` — the board snapshot | struct + vectors | Main | Render | `g_board.lock` |
| ImGui IO | ImGui globals | Input, Window, Render | same | `g_imguiIoMx` |
| Config values a live re-read can change | atomics | Main | Main, Render | atomic per value |

**The authoritative store has no lock and must never acquire one.** It is
main-thread-only by construction: sinks queue to main, serialization
callbacks run on main, board edits queue to main. If a future change wants to
read `g_followers` off-thread, the answer is a snapshot, never a lock —
adding a lock here would put engine calls under it and reintroduce MAO's
re-entrant self-deadlock.

**`g_board.lock` and `g_imguiIoMx` are never nested.** Copied from MEO, which
documents them as having no cross-lock. `g_imguiIoMx` is held around the IO
block only and **released before the engine passthrough** in the input hook.

### 3.2 Flow direction

```
 sinks / board input  ──queue──▶  SKSE task (MAIN)  ──mutates──▶  g_followers
                                        │
                                        └──publishes──▶ g_board (under lock)
                                                              │
 render thread ────────────────────reads snapshot─────────────┘
```

Nothing flows the other way. The render thread never reaches into
`g_followers`, and no engine call is ever made from the present hook.

## 4. The tick pipeline (the novel subsystem)

End to end, one service tick:

1. **Frame clock (render).** The present hook increments `g_frameCount` and
   records `g_frameDeltaMs`. Two atomic stores, no logic, no allocation.
2. **Pump (main).** A self-requeuing `AddTask` runs once per frame. It reads
   the frame clock and asks: has `max(4 frames, 133 ms)` elapsed since the
   last tick? If no, requeue and return — **this is the common case and it
   must cost nothing**.
   - **The pump does NOT depend on the render hook.** If D3D init failed the
     board is disabled but the evaluator must still work, so the clock falls
     back to `std::chrono`. The frame counter is a refinement, not a
     dependency (`INVARIANTS` #16).
   - **Never catch up.** Fire at most once per wake and set `last = now`.
     A stall must not produce a burst (`INVARIANTS` #15).
3. **Select (main).** The scheduler picks K followers from the shuffled,
   aged round-robin (`DESIGN.md` §4.1a), skipping any that are unresolvable,
   low-process, dead, in dialogue, or inside a suppression window whose
   position blocks every rule they have.
4. **Snapshot (main).** Per-follower cheap state is read directly. The
   **shared world snapshot is built lazily** — only if a selected follower
   reaches an expensive-tier predicate this tick — and is then reused by any
   other follower serviced on the same tick.
5. **Scan (main).** Rules top-down from rule 1, **against the combat table in
   combat and the logistics table out of it** — never both in one tick. First
   true condition wins; evaluation stops. Positional suppression applies: a
   rule at or below the currently-suppressing position is skipped
   (`DESIGN.md` §4.4).
6. **Actuate (main).** Execute the one selected action. Open a suppression
   window sized to the action, recording **the rule's position**, not just a
   deadline.
7. **Record.** Store the per-rule outcome (fired / failed + reason) for the
   board's §5.3 display. This is the only state the tick leaves behind, and
   it is display-only — **the evaluator never reads it back** (`INVARIANTS`
   #14).

**Step 4's laziness is the performance design.** A list of only cheap
predicates never builds the world snapshot at all.

## 5. Hook inventory

**Gameplay code hooks: ZERO.** Tier A actuation is entirely engine calls and
event sinks (`DESIGN.md` §4.5). This is a deliberate architectural property,
not an accident — it means MFO has no Address-Library exposure in its core
loop and cannot be broken by a game update in the way a hooked mod can.

**Board hooks: three**, lifted from MEO, all installed in `SKSEPluginLoad`
before the renderer exists, `SKSE::AllocTrampoline(256)`:

| Hook | RelocationID | Offset | Thread | Purpose |
|---|---|---|---|---|
| D3DInit | `(75595, 77226)` | `VariantOffset(0x9, 0x275, 0x0)` | init | device/context/swapchain grab, ImGui init |
| DXGIPresent | `(75461, 77246)` | `Offset(0x9)` | render | draw + frame clock |
| InputDispatch | `(67315, 68617)` | `Offset(0x7B)` | input | translate and swallow input while open |

Plus a WndProc swap via `SetWindowLongPtrA` (not a trampoline hook).

**If Tier B ever needs a code hook**, it arrives under the full discipline:
Address Library ID only, published site from a maintained reference mod,
validated against crash-log ground truth, verified live against
`/proc/<pid>/mem`, self-verifying at install, INI-gated, **one per release**.

## 6. Event sinks

Registered on `RE::ScriptEventSourceHolder` at `kDataLoaded`; **all handlers
queue to main via `AddTask` and do no work inline.**

| Sink | Feeds | Gotcha |
|---|---|---|
| `TESDeathEvent` | Rapport income | **Fires twice — act only on `dead == true`.** Killer tested as player or teammate |
| `TESCombatEvent` | Combat-exit survival award; combat-state conditions | New to this family; no sibling precedent |
| `TESSpellCastEvent` | Board opener (fires for lesser powers) | Gate on `IsPlayerRef()` |
| `CrosshairRefEvent` | Board target selection | Via `SKSE::GetCrosshairRefEventSource()` |
| `MenuOpenCloseEvent` | Config re-read; **LoadingMenu-CLOSE as the gameplay-resumed anchor** | Never a blind timer — one fired during a long load is swallowed |
| `TESEquipEvent` | Debounced action-vocabulary refresh | **Dispatch is synchronous into follower AI and outfit managers** |

SKSE messaging: `kDataLoaded` (resolve forms, register sinks, load
vocabulary), `kPostLoadGame` / `kNewGame` (reconcile ledgers, re-assert
globals, seed the scheduler).

## 7. Co-save schema

Record `MFOD`, versioned. Readers for every shipped version are kept
**forever**; writers emit only the newest.

```
Globals:
  u32  schemaVersion
  u32  followerCount
Per follower:
  u32  actorFormID        -> ResolveFormID on load; unresolvable = drop record
  u32  rapport
  u8   rank               -> clamped [1,5]
  u8   tableCount         -> 2 (Combat, Logistics). Written EXPLICITLY so a
                             third table is an append, not a reinterpretation
  Per table:
   u8  gambitCount        -> clamped to THAT TABLE's slot max for the rank
                             (combat and logistics ladders differ, DESIGN 5.2).
                             Over-cap gambits are still fully CONSUMED from the
                             stream before being dropped -- bailing early would
                             desync everything after them
   Per gambit:
    str  conditionOpcode  -> stable string id, NEVER an enum ordinal
    f32  conditionParam
    u8   subjectSelector
    str  actionOpcode
    u32  actionParamForm  -> ResolveFormID; unresolvable = disable THIS rule
    u8   flags            -> enabled bit
  u16  overrideCount
    u32 packageFormID, u8 priority
```

**Schema history — readers kept forever (INVARIANTS #12):**

| Version | Shipped in | Layout |
|---|---|---|
| **v1** | v0.1.0 – v0.3.0 | `{rapport, rank, tables[], tutored[], overrides[]}` |
| **v2** | v0.4.0+ | `{rapport, rank, tables[], overrides[]}` — tutoring out of scope (`DESIGN.md` §5.4) |

The v1 reader survives and **consumes and discards** the tutored block;
skipping the read rather than performing it would desync every byte after it.

**A near-miss worth recording.** The tutored block was first deleted at v1
*without* a bump, justified by "no save has ever contained an MFO record" —
which was true when written and stopped being true the moment saving with the
mod active was planned. A v0.3.0 save read by a v0.4.0 DLL would have
misparsed, and the newer-than-me guard could not have caught it because both
claim v1. **"Nobody has data yet" is a fact with an expiry date; a version
number is not.**

**Not serialized:** anything derived (current rank thresholds, vocabulary
tables, suppression state, the board snapshot, per-rule outcomes). Derived
state is rebuilt at load; persisting it is how schemas rot.

`RevertCallback` zeroes everything save-scoped, including the scheduler's
round-robin cursor.

## 8. Generator ↔ DLL contracts

Two compile-time contracts, both of which break silently if violated.

**8.1 FormID band** (`DESIGN.md` §8.2). `MFO_GenerateESP.py` emits the ESP;
`data/mfo_forms.frozen.json` anchors allocation; `tools/audit_esp.py` must
PASS as a merge gate. The DLL resolves each form at `kDataLoaded` by
`(localID, "MFO.esp")` and disables the dependent feature with a log line if
one is missing — never a hard requirement.

**8.2 Vocabulary codegen.** `tools/gen_vocab_header.py` turns
`data/vocabulary.json` into `native/Vocabulary.h` — `constexpr` tables of
conditions (opcode string, subject kind, cost tier, urgency tier) and action
kinds. **No runtime JSON parsing in the DLL**: no file paths to break
in-game, no parser dependency, and the table cannot drift from the code
consuming it. The same JSON generates the board's display strings and the MCM
`config.json`, so **generator text and DLL behavior are one source** —
tooltips that disagree with behavior are a shipped lie.

**The opcode strings in that JSON are a persistence contract.** They land in
co-saves. Renaming one is a schema migration, not an edit.

## 9. Startup order

`kDataLoaded`:
1. Read config (INI, then MCM Helper's file — last wins).
2. Resolve `MFO.esp` forms; log each failure by name.
3. Register event sinks.
4. Validate the compiled vocabulary (opcode uniqueness, tier sanity).

`kPostLoadGame` / `kNewGame` — **after** the co-save has loaded:
1. Grant the Field Orders power if absent (retry next load if it fails; never
   burn the latch on a failed grant).
2. Reconcile the tutored-spell ledger against actual `HasSpell` state.
3. Reconcile package overrides against `CountPackageOverride`.
4. Re-assert any GlobalVariable handshakes (**globals are save-persisted and
   a data-load write is overwritten by the save**).
5. Seed the scheduler clock; clear suppression state.

Order matters at every step: 3 before 1 in the `kDataLoaded` block would
register sinks that fire against unresolved forms; the co-save must be loaded
before any reconcile, or the ledger looks empty and MFO revokes nothing.

## 10. What is deliberately absent

- **No runtime Papyrus.** One compile-time MCM stub, no tracker quest, no
  heartbeat script. Do not ship VMADs for scripts you don't ship.
- **No installer, no patch plugin, no calibration pass.** Unlike MEO and MAO,
  MFO bakes nothing from a load order — its data surface is the actor in
  front of you (`DESIGN.md` §8.2).
- **No leveled-list edits, no record overrides.** `MFO.esp` adds; it never
  overwrites.
- **No dedicated threads.** The pump is a self-requeuing main-thread task.
